# PRP 03.5 — Teacher: Schedule + ClassSession Lifecycle

> **Implementation update (Phase 4.6 / PRP 06):** lifecycle decision ยังใช้ได้ แต่ QR-related schema ที่เคยเตรียมไว้ถูกปรับแล้ว
>
> - `ClassSession` ยังผูกกับ `Schedule`, มี `startsAt`, `endsAt`, `lateAfter`, `isOpen`, `closedAt`
> - QR rotation fields (`qrTokenExpiresAt`, `qrRefreshedAt`) ถูกลบออกแล้ว
> - Session ที่เปิดอยู่ใช้ static `qrToken` + static `entryCode` จนกว่าจะปิด
> - Lazy auto-close ปัจจุบันใช้ safety timeout ที่ `endsAt + 30 นาที`

> **Phase:** 3.5 (after Phase 3 — Courses + Roster)
> **Demo gate:** teacher login → /teacher/courses/[id] → tab "ตารางสอน" → เพิ่ม slot จันทร์ 9:00-12:00 ห้อง SC-3001 → กลับไป /teacher → เห็น "ตารางสอนวันนี้" (ถ้าวันนี้ตรง) → กด "เปิด session" → redirect /teacher/sessions/[id] (skeleton) → กด "ปิด session"

---

## Goal

ให้อาจารย์:
1. **กำหนดตารางสอนรายสัปดาห์** ของแต่ละวิชา (recurring weekly)
2. **เปิด/ปิดคาบเรียน (ClassSession)** ที่ผูกกับ Schedule slot
3. **ดูตารางสอน "วันนี้"** บน dashboard ที่ดึงจากฐานข้อมูลจริง

เป้าหมายเชิง architecture:
- Lifecycle ของ ClassSession ปลอดภัย — กัน double-open ที่ระดับ DB ไม่ใช่แค่ application
- ไม่มี background job / cron — lazy auto-close ตอน read
- รองรับ Phase 4 (QR display) ทันทีโดยไม่ต้อง refactor schema

---

## Non-goals (ไม่ทำใน Phase 3.5)

- QR token generation / display / refresh ทุก 30s — **Phase 4**
- One-off / makeup-class scheduling — เปิด session นอกวัน schedule ได้อยู่แล้ว (flexible day check)
- Cron job / background worker / Vercel Cron — ใช้ lazy auto-close แทน
- Schedule overlap detection (เช่น Mon 9-12 + Mon 11-14) — Phase 6 ถ้ามีเวลา
- Student-side ดูตารางสอนตัวเอง — Phase 4.5
- Late detection (`lateAfter`) — Phase 4 (ตอนทำ QR + check-in)
- Session attendance summary / count — Phase 5

## Decisions Summary (จากการคุยรอบนี้)

| # | จุด | เลือก | เหตุผล |
| -- | --- | ----- | ------ |
| 1 | Schedule pattern | Recurring weekly | ตารางสอน ม.ธรรมศาสตร์คงที่ทั้งเทอม |
| 2 | Session binding | Must bind (`scheduleId` NOT NULL) | กันสร้าง session ลอย ไม่มี context |
| 3 | Open mechanism | Manual (ครูกดปุ่ม) | ลด moving parts (ไม่ต้องมี cron) + ครู control เต็ม |
| 4 | Close behavior | Hybrid: manual + safety timeout (lazy auto-close) | กัน session ค้างเปิด โดยไม่ต้องมี background worker |
| 5 | Multi-slot per course | Yes (1 course → N schedules) | รองรับ lecture + lab, หรือคอร์สที่สอนหลายวัน/สัปดาห์ |
| 6 | Day strictness | Flexible (เปิดวันไหนก็ได้) | รองรับคาบชดเชย/เลื่อน — ไม่ต้องสร้าง one-off slot |
| 7 | Schedule delete | Block if has sessions (`onDelete: Restrict`) | ปลอดภัยสุด ข้อมูล audit ไม่หาย |

## Schema Touch Points

### NEW: `Schedule` model

```prisma
model Schedule {
  id        String   @id @default(cuid())
  courseId  String

  dayOfWeek Int      // 0=Sun, 1=Mon, ..., 6=Sat (match JS Date.getDay())
  startTime String   // "HH:MM" 24h, e.g. "09:00"
  endTime   String   // "HH:MM" 24h, e.g. "12:00"
  room      String?  // optional, e.g. "SC-3001"

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  course        Course         @relation(fields: [courseId], references: [id], onDelete: Restrict)
  classSessions ClassSession[]

  @@index([courseId])
  @@index([dayOfWeek])
}
```

**Why these field choices:**
- `dayOfWeek` Int 0-6 ตรงกับ `new Date().getDay()` ของ JS — ลด bug จาก ISO 8601 (1=Mon) conversion
- `startTime` / `endTime` String "HH:MM" — readable, sortable lex (HH:MM 24h เปรียบเทียบ string ได้ตรงกับเปรียบเทียบเวลา), ไม่มี timezone issue (มันคือ "เวลาในวัน" ไม่ใช่ instant)
- `room` nullable — บางคอร์สเรียนออนไลน์/ไม่ระบุห้อง
- `Course` relation ใช้ `onDelete: Restrict` — ลบ Course ที่มี schedule ไม่ได้ (เคารพ pattern เดียวกับ teacher relation)

### MODIFY: `ClassSession` model

```prisma
model ClassSession {
  id         String    @id @default(cuid())
  courseId   String
  scheduleId String    // ← NEW: must bind to Schedule
  startsAt   DateTime
  endsAt     DateTime
  lateAfter  DateTime?

  qrToken          String?   @unique
  qrTokenExpiresAt DateTime?
  qrRefreshedAt    DateTime?

  isOpen    Boolean  @default(true)
  closedAt  DateTime?  // ← NEW: เก็บเวลาปิดจริง (manual หรือ auto)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  course      Course       @relation(fields: [courseId], references: [id], onDelete: Cascade)
  schedule    Schedule     @relation(fields: [scheduleId], references: [id], onDelete: Restrict)
  attendances Attendance[]

  @@index([courseId])
  @@index([scheduleId])
  @@index([startsAt])
  @@index([qrToken])
  // Partial unique index ↓ เขียน raw SQL ใน migration (Prisma 5 ไม่รองรับ where ใน @@unique)
}
```

**ความสำคัญของ partial unique index:**

```sql
-- prisma/migrations/<ts>_phase35_schedule_session/migration.sql
CREATE UNIQUE INDEX "ClassSession_one_open_per_course"
  ON "ClassSession" ("courseId")
  WHERE "isOpen" = true;
```

นี่คือกุญแจสำคัญของ Phase 3.5 — **กัน double-open ระดับ DB**:
- ถ้าครูกด "เปิด session" 2 ครั้งเร็วๆ (race condition) → DB จะปฏิเสธอันที่สอง
- ถ้า attacker ส่ง POST `openSession` ตรงๆ ซ้ำๆ → DB block ตั้งแต่ insert
- เมื่อปิด session แล้ว `isOpen=false` → constraint ปล่อยให้เปิดใหม่ได้

**Why `closedAt` field ใหม่:**
- ปัจจุบัน `isOpen=false` แค่บอก "ปิดแล้ว" แต่ไม่รู้ว่าปิดเมื่อไหร่ (manual? auto?)
- เก็บไว้สำหรับ Phase 5 (report — "session นี้ปิดเมื่อ 12:30 — ใครเช็คอินหลังจากนั้นเป็น ABSENT")

### Migration name suggestion

```
npx prisma migrate dev --name phase35_schedule_session
```

Migration จะมี 2 ส่วน:
1. Auto-generated: `CREATE TABLE Schedule`, `ALTER TABLE ClassSession ADD scheduleId/closedAt`
2. **Manual edit** ของ migration.sql: ใส่ `CREATE UNIQUE INDEX ... WHERE isOpen=true;` ก่อน apply

⚠️ **ถ้ามี ClassSession แถวเก่าใน DB** (เพราะ `scheduleId` NOT NULL) — ตอน migrate จะ fail ต้อง:
- Plan A (ดีกว่า): ตอนนี้ยังไม่มี ClassSession seed → migrate ได้เลย
- Plan B: ถ้า dev DB มี seed test session → ลบก่อน migrate (`prisma migrate reset`)
- ปัจจุบัน `prisma/seed.ts` มีแค่ User → Plan A ใช้ได้

### `openSession(scheduleId)`

```ts
"use server";
// Auth: ดึง schedule.courseId แล้ว requireCourseOwner
// Action:
//   1. โหลด Schedule
//   2. คำนวณ startsAt = today (server tz Asia/Bangkok) + Schedule.startTime
//      endsAt   = today + Schedule.endTime
//      ⚠️ Server-side คำนวณเท่านั้น — ห้ามรับ startsAt จาก client (anti-tampering)
//   3. db.classSession.create({ courseId, scheduleId, startsAt, endsAt, isOpen: true })
//      - catch Prisma P2002 (unique violation) → return error
//        "มี session ของวิชานี้ที่เปิดอยู่แล้ว — กรุณาปิดก่อน"
//   4. redirect(`/teacher/sessions/${newSession.id}`)
```

**Edge case — flexible day:**
- Schedule.dayOfWeek = 1 (Mon) แต่ครูเปิดวันพุธ → **อนุญาต** (คาบชดเชย)
- UI แสดง warning ใน dashboard ว่า "ไม่ตรงตารางปกติ" (Phase 4.5 ถ้ามีเวลา) — Phase 3.5 ไม่ต้องทำ

### `closeSession(sessionId)`

```ts
"use server";
// Auth: ดึง session.courseId แล้ว requireCourseOwner
// Action: db.classSession.update where { id, isOpen: true }
//   data: { isOpen: false, closedAt: new Date() }
// Idempotent: ถ้า isOpen=false อยู่แล้ว update จะ no-op (where filter)
// Revalidate: /teacher, /teacher/courses/[courseId], /teacher/sessions/[id]
```

### Helper: `autoCloseIfExpired(session)` — `src/lib/session-helpers.ts`

```ts
import "server-only";

const SAFETY_TIMEOUT_MIN = 30;

export async function autoCloseIfExpired(session: ClassSession) {
  if (!session.isOpen) return session;
  const expiresAt = new Date(session.endsAt.getTime() + SAFETY_TIMEOUT_MIN * 60 * 1000);
  if (Date.now() < expiresAt.getTime()) return session;

  // Lazy close
  return db.classSession.update({
    where: { id: session.id, isOpen: true },
    data: { isOpen: false, closedAt: expiresAt },
  });
}
```

**เรียกใช้ที่:**
- `/teacher/sessions/[id]` page (server component) — ก่อน render
- `/teacher` dashboard ตอน list active sessions (Phase 5)

**Why lazy ไม่ใช่ cron:**
- MVP ไม่ต้อง infra เพิ่ม
- Trade-off: session ที่ไม่มีใครเข้าดูจะค้างเปิดใน DB จนกว่าจะมี read — ไม่กระทบ business logic เพราะ student check-in ก็ผ่าน autoCloseIfExpired ก่อน insert attendance (Phase 4.5)
- ถ้าโต mature → Phase 6 เพิ่ม Vercel Cron นัด `closeExpiredSessions()` รายวัน

## Security

### 3-Layer Defense Recap (Layer 3 = ของจริง)

| Action | Authoritative check |
| ------ | ------------------- |
| `createSchedule` | `requireCourseOwner(courseId)` |
| `deleteSchedule` | โหลด schedule → `requireCourseOwner(schedule.courseId)` |
| `openSession` | โหลด schedule → `requireCourseOwner(schedule.courseId)` |
| `closeSession` | โหลด session → `requireCourseOwner(session.courseId)` |
| Page `/teacher/sessions/[id]` | โหลด session → `requireCourseOwner(session.courseId)` |

### Specific threats

| # | ภัยคุกคาม | การกัน |
| -- | -------- | ------ |
| 1 | **IDOR**: ครู A เปิด session ของครู B | `requireCourseOwner` ก่อนเปิด |
| 2 | **Double-open** (race / replay) | DB partial unique index ที่ระดับ database |
| 3 | **Time tampering**: ครูส่ง `startsAt` ในอดีต/อนาคต | Server คำนวณ startsAt จาก Schedule + today เท่านั้น — ไม่รับ client input |
| 4 | **Stale session ค้าง** | `autoCloseIfExpired()` ตอน read |
| 5 | **Schedule delete ทำ session orphan** | `onDelete: Restrict` ที่ DB-level |

### Input validation (Zod)

ไฟล์: `src/lib/validations/schedule.ts`

```ts
export const TIME_HHMM = /^([01]\d|2[0-3]):[0-5]\d$/;

export const createScheduleSchema = z.object({
```

## Anti-patterns (ห้ามทำ)

1. **ห้ามใช้ Prisma `@@unique([courseId])` แทน partial unique** — มันจะกันสร้าง session ซ้ำตลอดกาล ไม่ใช่เฉพาะตอน open. ใช้ raw SQL `WHERE isOpen=true` เท่านั้น
2. **ห้ามรับ `startsAt`/`endsAt` จาก client** ใน `openSession` — server คำนวณเอง (anti-tampering)
3. **ห้ามตั้ง `scheduleId` เป็น nullable** — Phase 3.5 ตัดสินใจ "must bind" แล้ว, การเปลี่ยนทีหลัง = data migration ที่เจ็บปวด
4. **ห้ามทำ application-level check แทน DB unique** — เช่น `if (await db.findFirst(...isOpen)) throw` แล้ว create — race condition จะ slip through. ให้ DB เป็น source of truth
5. **ห้ามเขียน cron job / setInterval ใน Server Component** — lazy auto-close พอแล้ว
6. **ห้ามลืม `revalidatePath`** หลังทุก mutation — UI จะแสดงข้อมูลเก่า
7. **ห้าม `onDelete: Cascade` บน `Schedule.classSessions`** — ลบ schedule ทำ attendance หาย (เคารพ decision #7)
8. **ห้ามใช้ `Date.now()` หรือ client time ในการตัดสิน open/close** — ใช้ server-side `new Date()` เท่านั้น

## Tradeoffs (สำหรับอธิบายอาจารย์)

| Decision | Trade-off ที่รับ | ทำไมรับได้ |
| -------- | --------------- | ---------- |
| Recurring weekly เท่านั้น | ทำคาบชดเชย/seminar one-off ตรงๆ ไม่ได้ | ใช้ flexible day check + open จาก slot ใกล้เคียงแทน — UX ที่จริงครูเข้าใจ + ลด schema complexity |
| Lazy auto-close (no cron) | Session ที่ไม่มีคนเข้าดูจะค้างใน DB จนมี read | กระทบแค่ data hygiene ไม่กระทบ business — Phase 6 เพิ่ม cron ทีหลังได้ |
| Manual open ไม่ auto จาก schedule | ครูต้องเปิดเอง (อาจลืม) | ลด moving parts (cron, scheduled jobs) + ครูมี control — ลืมก็เปิดย้อนหลังได้เพราะ flexible day |
| `dayOfWeek` Int 0-6 ไม่ใช่ enum | type safety น้อยกว่า enum | ตรงกับ JS native `Date.getDay()` — ลด conversion bug |
| `startTime` String ไม่ใช่ Int (minutes) | คำนวณเวลาต้อง parse | อ่าน DB ตรงๆ เข้าใจง่าย, sortable, debug ง่าย, lex compare = time compare ใน HH:MM 24h |
| Partial unique index (raw SQL) | ออกจาก Prisma DSL ไป SQL | Prisma 5 ไม่รองรับ partial — DB-level enforcement สำคัญกว่า keep-in-DSL |
| Block schedule delete ถ้ามี session | ครูลบ schedule ที่ไม่ใช้แล้วไม่ได้ | safer default — ใน Phase 6 เพิ่ม archive flag ได้ |
